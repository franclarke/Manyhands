## Bloqueo D1 — defecto productivo en el commit congelado

`main` @ `1e842e4` **no typechequea**. `pnpm build` falla en el paso DTS de
`@manyhands/decomposer` (los bundles ESM/CJS sí se emiten). Cuatro errores,
todos introducidos por `73e3ed8` (`chore: consolidate semantic planning and
thesis artifacts`):

1. `src/planner/semantic-plan.ts:6` — TS2724: importa `RepositoryEvidence` de
   `./schema.js`, que sólo exporta `RepositoryEvidenceSchema`.
2. `src/planner/planning-module.ts:10` — TS2459: `RepositoryEvidence` está
   declarado localmente en `./semantic-plan.js` pero no exportado.
3. `src/planner/planning-module.ts:256` — TS2375: `offsetObserver` viola
   `exactOptionalPropertyTypes`.
4. `src/planner/planning-module.ts:264` — TS2322: `normalizeModelOutputs`
   devuelve `ParseJsonObjectCandidatesResult` donde se espera `unknown[]`.

El cuarto **no es sólo un error de tipos: rompe la ruta que SP2 existe para
validar**.

- `planning-module.ts:183` hace `normalizeModelOutputs(await model.generate(...))`
  y `:194` itera el resultado con `for…of`.
- El modelo productivo es `invokeSelectedPlanningCli`
  (`run-coordinator-host.ts:73`), que devuelve `Promise<string>`.
- Con una string, `normalizeModelOutputs` devuelve el objeto
  `{ok, candidates, invalidCandidateCount}`, que no es iterable.
- `planning-host.ts:120` toma esa rama siempre que la celda no declare
  `experimentalCandidate` — el caso de las dos celdas SP2 — y `:138` convierte
  el rechazo en un `throw`.

**Reproducción contra el `dist` construido** (probe de sólo lectura, sin tocar
el producto), con un modelo stub:

```
string output (productive CLI shape): kind=rejected
  message=outputs is not iterable

array output (control):               kind=rejected
  message=root: Invalid input; root: Unrecognized key(s) in object: 'anything'
```

El control con array llega a la validación de schema, así que el fallo es
específico de la salida string y no del stub. Conclusión: **con cualquier
executor CLI, ninguna celda SP2 puede producir un plan candidato**. El fallo es
determinista y anterior a cualquier decisión de granularidad o de seams.

No se corrigió: el prompt prohíbe modificar ManyHands durante el experimento.
