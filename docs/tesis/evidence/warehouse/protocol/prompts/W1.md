# W1 — Layout e inventario determinista

## Goal

Construí el primer incremento funcional de Warehouse Control Tower: un modelo
de zonas, pasillos y bins con inventario por SKU y un escenario reproducible
`thesis-seed-2026`.

## Acceptance

- El escenario contiene al menos 3 zonas, 12 bins y 3 SKUs con stock positivo.
- Operaciones de ingreso, retiro y transferencia preservan cantidades y
  rechazan stock negativo o bins desconocidos.
- La sonda usa el dominio productivo y emite la salida descrita en
  «Probe contract», derivada del escenario y no de valores fijos.
- Tests, typecheck y build quedan verdes.

## Probe contract

El comando `pnpm study:probe -- --increment W1 --scenario thesis-seed-2026 --format json`
escribe en stdout un único objeto JSON y ninguna otra salida, con exactamente
esta forma:

```json
{
  "schemaVersion": 1,
  "increment": "W1",
  "scenario": "thesis-seed-2026",
  "stateHash": "sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "capabilities": {
    "layout": {
      "zones": 4,
      "bins": 16
    },
    "inventory": {
      "skus": 5,
      "totalUnits": 240
    }
  }
}
```

La envoltura fija `schemaVersion`, `increment` y `scenario`. Las capacidades
requeridas en este incremento son `layout`, `inventory`.
Cada una vive anidada dentro de `capabilities`: ninguna se publica en el nivel
superior ni se renombra.

Los valores del ejemplo son ilustrativos. Derivalos del escenario respetando
estos mínimos e invariantes, que el oráculo externo verifica:

- `layout.zones` es un número >= 3.
- `layout.bins` es un número >= 12.
- `inventory.skus` es un número >= 3.
- `inventory.totalUnits` es un número >= 1.

`stateHash` es la cadena `sha256:` seguida de 64 dígitos hexadecimales
minúsculos. Dos invocaciones sobre el mismo commit emiten bytes idénticos.

## Constraints

- Base: domain-free seed commit from `seed-manifest.json`.
- No fixtures, respuestas hardcodeadas ni una segunda implementación para la
  sonda; el mismo seed debe producir bytes JSON deterministas.
- Elegí boundaries cohesivos sin asumir la arquitectura de referencia.

## Oracle

Oracle id: `warehouse-w1-v1`. El oráculo externo ejecuta los comandos del repo,
invoca dos veces la sonda y verifica layout, inventario y determinismo.
