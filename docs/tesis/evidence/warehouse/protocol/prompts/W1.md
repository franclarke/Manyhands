# W1 — Layout e inventario determinista

## Goal

Construí el primer incremento funcional de Warehouse Control Tower: un modelo
de zonas, pasillos y bins con inventario por SKU y un escenario reproducible
`thesis-seed-2026`.

## Acceptance

- El escenario contiene al menos 3 zonas, 12 bins y 3 SKUs con stock positivo.
- Operaciones de ingreso, retiro y transferencia preservan cantidades y
  rechazan stock negativo o bins desconocidos.
- `pnpm study:probe -- --increment W1 --scenario thesis-seed-2026 --format json`
  usa el dominio productivo y emite schema 1, `stateHash`, `layout` e `inventory`.
- Tests, typecheck y build quedan verdes.

## Probe contract

Campos exactos: `schemaVersion`, `increment`, `scenario`, `stateHash`,
`capabilities`, `layout` e `inventory`.

El comando de la sonda escribe únicamente un objeto JSON determinista con esta
envoltura exacta: `schemaVersion: 1`, `increment: "W1"`,
`scenario: "thesis-seed-2026"`, `stateHash: "sha256:<64 hex minúsculos>"` y
`capabilities`. Este último contiene `layout: { zones, bins }` con valores
numéricos mínimos 3 y 12, e `inventory: { skus, totalUnits }` con mínimos 3 y
1. No renombrar, anidar ni sustituir estos campos.

## Constraints

- Base: domain-free seed commit from `seed-manifest.json`.
- No fixtures, respuestas hardcodeadas ni una segunda implementación para la
  sonda; el mismo seed debe producir bytes JSON deterministas.
- Elegí boundaries cohesivos sin asumir la arquitectura de referencia.

## Oracle

Oracle id: `warehouse-w1-v1`. El oráculo externo ejecuta los comandos del repo,
invoca dos veces la sonda y verifica layout, inventario y determinismo.
