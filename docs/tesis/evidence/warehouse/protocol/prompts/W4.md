# W4 — API, SSE y reloj de simulación

## Goal

Exponé el estado Warehouse mediante API HTTP y un stream Server-Sent Events;
agregá simulación determinista con controles play, pause, step y reset visibles.

## Acceptance

- API y SSE comparten contratos versionados; la secuencia de eventos es
  monótona y reconectable.
- Step procesa exactamente un tick; reset reproduce el estado inicial; pause no
  avanza el reloj.
- La UI refleja conexión y reloj sin ocultar errores.
- La sonda W4 agrega `simulation` con al menos 4 eventos, controles completos y
  secuencia SSE monótona; preserva W1–W3 y pasan todos los gates.

## Probe contract

El comando `pnpm study:probe -- --increment W4 --scenario thesis-seed-2026 --format json`
escribe en stdout un único objeto JSON y ninguna otra salida, con exactamente
esta forma:

```json
{
  "schemaVersion": 1,
  "increment": "W4",
  "scenario": "thesis-seed-2026",
  "stateHash": "sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "capabilities": {
    "layout": {
      "zones": 4,
      "bins": 16
    },
    "inventory": {
      "skus": 5,
      "totalUnits": 240
    },
    "visual": {
      "svgElements": 64,
      "heatmapCells": 16,
      "textLabels": 12
    },
    "orders": {
      "accepted": 3,
      "rejected": 1,
      "reservationConserved": true
    },
    "simulation": {
      "events": 12,
      "playPauseStepReset": true,
      "sseMonotonic": true
    }
  }
}
```

La envoltura fija `schemaVersion`, `increment` y `scenario`. Las capacidades
requeridas en este incremento son `layout`, `inventory`, `visual`, `orders`, `simulation`.
Cada una vive anidada dentro de `capabilities`: ninguna se publica en el nivel
superior ni se renombra.

Los valores del ejemplo son ilustrativos. Derivalos del escenario respetando
estos mínimos e invariantes, que el oráculo externo verifica:

- `layout.zones` es un número >= 3.
- `layout.bins` es un número >= 12.
- `inventory.skus` es un número >= 3.
- `inventory.totalUnits` es un número >= 1.
- `visual.svgElements` es un número >= 1.
- `visual.heatmapCells` es un número >= 12.
- `visual.textLabels` es un número >= 3.
- `orders.accepted` es un número >= 1.
- `orders.rejected` es un número >= 1.
- `orders.reservationConserved` es exactamente `true`.
- `simulation.events` es un número >= 4.
- `simulation.playPauseStepReset` es exactamente `true`.
- `simulation.sseMonotonic` es exactamente `true`.

`stateHash` es la cadena `sha256:` seguida de 64 dígitos hexadecimales
minúsculos. Dos invocaciones sobre el mismo commit emiten bytes idénticos.

## Constraints

- Base: verified delivery of W3.
- Sin sleeps como fuente de determinismo ni stream simulado sólo para tests.
  Los adapters llaman al mismo motor y contratos productivos.

## Oracle

Oracle id: `warehouse-w4-v1`. Verifica cadena acumulativa, reloj y SSE.
