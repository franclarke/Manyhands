# W7 — Persistencia, replay y timeline

## Goal

Persistí un log append-only y snapshots, reconstruí el estado por replay y
mostrá un timeline navegable con alertas de stock, bloqueo y congestión.

## Acceptance

- Replay completo y restore desde snapshot producen el mismo hash que estado
  vivo; eventos corruptos o fuera de secuencia fallan explícitamente.
- Timeline permite inspeccionar al menos 4 eventos y volver al presente.
- Alertas tienen severidad y texto accesible.
- La sonda W7 agrega `persistence` con igualdad de replay, restore y conteo de
  timeline; preserva W1–W6 y pasan todos los gates.

## Probe contract

El comando `pnpm study:probe -- --increment W7 --scenario thesis-seed-2026 --format json`
escribe en stdout un único objeto JSON y ninguna otra salida, con exactamente
esta forma:

```json
{
  "schemaVersion": 1,
  "increment": "W7",
  "scenario": "thesis-seed-2026",
  "stateHash": "sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "capabilities": {
    "layout": {
      "zones": 4,
      "bins": 16
    },
    "inventory": {
      "skus": 5,
      "totalUnits": 240
    },
    "visual": {
      "svgElements": 64,
      "heatmapCells": 16,
      "textLabels": 12
    },
    "orders": {
      "accepted": 3,
      "rejected": 1,
      "reservationConserved": true
    },
    "simulation": {
      "events": 12,
      "playPauseStepReset": true,
      "sseMonotonic": true
    },
    "routing": {
      "pickStops": 4,
      "distance": 18,
      "overlayVisible": true
    },
    "congestion": {
      "waves": 2,
      "capacityEnforced": true,
      "costInfluencesRoute": true
    },
    "persistence": {
      "timelineEvents": 12,
      "replayMatchesLive": true,
      "snapshotRestores": true
    }
  }
}
```

La envoltura fija `schemaVersion`, `increment` y `scenario`. Las capacidades
requeridas en este incremento son `layout`, `inventory`, `visual`, `orders`, `simulation`, `routing`, `congestion`, `persistence`.
Cada una vive anidada dentro de `capabilities`: ninguna se publica en el nivel
superior ni se renombra.

Los valores del ejemplo son ilustrativos. Derivalos del escenario respetando
estos mínimos e invariantes, que el oráculo externo verifica:

- `layout.zones` es un número >= 3.
- `layout.bins` es un número >= 12.
- `inventory.skus` es un número >= 3.
- `inventory.totalUnits` es un número >= 1.
- `visual.svgElements` es un número >= 1.
- `visual.heatmapCells` es un número >= 12.
- `visual.textLabels` es un número >= 3.
- `orders.accepted` es un número >= 1.
- `orders.rejected` es un número >= 1.
- `orders.reservationConserved` es exactamente `true`.
- `simulation.events` es un número >= 4.
- `simulation.playPauseStepReset` es exactamente `true`.
- `simulation.sseMonotonic` es exactamente `true`.
- `routing.pickStops` es un número >= 2.
- `routing.distance` es un número >= 1.
- `routing.overlayVisible` es exactamente `true`.
- `congestion.waves` es un número >= 2.
- `congestion.capacityEnforced` es exactamente `true`.
- `congestion.costInfluencesRoute` es exactamente `true`.
- `persistence.timelineEvents` es un número >= 4.
- `persistence.replayMatchesLive` es exactamente `true`.
- `persistence.snapshotRestores` es exactamente `true`.

`stateHash` es la cadena `sha256:` seguida de 64 dígitos hexadecimales
minúsculos. Dos invocaciones sobre el mismo commit emiten bytes idénticos.

## Constraints

- Base: verified delivery of W6.
- Persistir hechos reales del flujo productivo; no generar un journal separado
  exclusivamente para el oráculo.
