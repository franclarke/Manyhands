# Frontend Implementation Handoff

This document is the handoff for implementing the first read-only DAG canvas in `apps/web`. It is written for Claude Code or another implementation agent that will adapt the Claude Design direction into real React components.

## Current State

`apps/web` is a real Next.js 15 App Router application with TypeScript and Tailwind. It has a sober developer-tool shell and these routes:

- `/`
- `/build`
- `/lab`
- `/lab/benchmarks`
- `/lab/reports`
- `/replay`
- `/replay/demo`

The app currently exposes Lab Mode first. It can list benchmark manifests, run deterministic mock benchmarks and display a `BenchmarkReport` summary. It does not have a DAG canvas yet.

## Available API Endpoints

- `GET /api/health`
- `GET /api/benchmarks`
- `GET /api/benchmarks/[id]`
- `POST /api/benchmarks/[id]/run`
- `GET /api/demo/run-snapshot`

The benchmark endpoints are backed by the existing core/evaluator packages. They are not UI-only mocks.

## Demo RunSnapshot Endpoint

Use this endpoint for the first read-only canvas:

```txt
GET /api/demo/run-snapshot?benchmark=conflict-v0&config=B4
```

Defaults:

- benchmark: `conflict-v0`
- config: `B4`
- feature: `shared-schema-conflict`

Optional query params:

- `benchmark=mock-v0 | conflict-v0`
- `config=B0 | B1 | B2 | B3 | B4`
- `feature=<feature-id>`

The endpoint returns one real `RunSnapshot` generated by `runBenchmarkMockFlow`. It does not persist the snapshot, run real agents, create worktrees, execute commands or use SQLite.

## Canvas Data Contract

The first UI-facing mapper lives at:

```txt
apps/web/src/lib/graph-view-model.ts
```

Use:

```ts
import { toRunGraphViewModel } from "@/lib/graph-view-model";
```

It maps:

```txt
RunSnapshot -> RunGraphViewModel
```

The view model includes:

- graph nodes from `snapshot.graphSnapshot.nodes`;
- dependency edges from `snapshot.graphSnapshot.dependencies`;
- risk edges from `snapshot.riskPredictions`;
- gate edges from `human_gate_decision_recorded` trace events;
- summary counts for tasks, leaves, dependencies, risks and trace events.

The mapper is intentionally independent from React Flow. The next phase can convert `GraphNodeView` and `GraphEdgeView` into React Flow nodes/edges without changing core schemas.

## Target Routes

Start with:

- `/replay/demo`: replace the current table preview with the first read-only DAG canvas.

Then extend:

- `/replay`: add entry points for snapshots/reports when persistence exists.
- `/lab/benchmarks`: link a generated benchmark run or report row to a snapshot replay view.

## Claude Design Import Plan

Import or adapt the Claude Design canvas as visual components, not as disconnected static state.

Use this sequence:

```txt
static design
  -> React components
  -> typed props from graph-view-model.ts
  -> API data from /api/demo/run-snapshot
  -> selected-node inspector
  -> later live state
```

Keep the visual direction, but preserve the real data path.

## Keep Real

The canvas implementation should keep these data sources real:

- `RunSnapshot` from `/api/demo/run-snapshot`;
- node and edge props from `graph-view-model.ts`;
- benchmark warnings in Lab Mode;
- report metadata and hashes;
- snapshot metadata and hashes;
- trace events and gate decisions.

## Do Not Implement Yet

Do not add these in the first canvas handoff implementation:

- real agents;
- real git worktrees;
- bottom-up integration;
- WebSockets;
- SQLite;
- graph editing;
- authentication;
- live execution state;
- report persistence;
- scheduler changes;
- core schema changes.

## Notes For The Next Agent

- Keep orchestration logic out of React components.
- Prefer small typed mappers over ad hoc component-side data digging.
- The first canvas should be read-only.
- Make mock/deterministic labels visible.
- Do not claim real execution, real merge conflicts or real agent evidence.
