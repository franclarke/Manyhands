## Auditoría por categorías (hallazgos)

Severidad: **P0** rompe confianza/legibilidad en demo · **P1** ruido o fricción
real · **P2** pulido.

### Observabilidad / debugging — el lente más importante del producto

- **[P0] El inspector ya recibe datos ricos y reales pero los presenta crudos.**
  `GET /api/runs/[id]/artifacts?ref=…` devuelve, por nodo:
  - `diff://` → git diff completo (archivos + SHA),
  - `log://` → log del agente: `status`, `exitCode`, `validation`, salida
    completa del test runner **con códigos ANSI**, y un *stdout tail* con el
    mensaje final del agente + `MH_STATUS`.
  Es exactamente la "terminal/logs por nodo" (objetivo B) — **y ya existe**. Pero
  el panel de foco:
  1. Muestra el **ref literal** `log://runs/…/node/slugify-module · cargando…`
     mientras resuelve → parece roto.
  2. Renderiza el log en un `<pre>` plano: los **códigos ANSI crudos**
     (`[32m✔`) se ven como basura `←[32m`.
  3. Esconde diff y log detrás de un `<details>` colapsado con summary mono
     diminuto. Para un nodo terminado, el diff y el log de tests son lo **más**
     valioso y están a un click escondido.
- **[P1] Copy obsoleto "Gemini".** La consola del nodo dice "Esperando output
  visible de **Gemini**…" y `focus-view.ts` comenta "Visible Gemini/process
  output". El proyecto migró a Claude Code / Codex (ADR 0031). En demo, decir
  "Gemini" mientras corre Claude rompe credibilidad.
- **[P1] Read amplification: `status://` se pollea cada 4s incluso en nodos/runs
  terminales.** El `ArtifactViewer` mantiene el poll de `status://` siempre;
  observé decenas de requests al mismo `status://slugify-module` en un run
  **completado**. Debe cortar el poll cuando el nodo no está vivo.

### Estados del sistema — claridad de estado

- **[P0] Etiqueta de estado inconsistente para el mismo run.** `aaeb1bf7` aparece
  como **"Completado"** en el sidebar y **"Revisión"** en el header del run. Dos
  fuentes, dos nombres, mismo run.
- **[P0] Run pausado en gate se muestra como "Ejecutando".** `88589e6f` está
  *suspendido* esperando decisión humana, pero el header pinta "● Ejecutando" con
  pulso ember. El propio doc del web-app dice que un run pausado debe mapear a
  `needs_review`, no a "Ejecutando".
- **[P1] La decisión de merge vive dispersa en 3 superficies** con 3 copys: header
  "Aprobar merge", panel de entrega "Mergear a master", y card de chat
  "Aprobar/Rechazar". El rediseño agent-first pide **un** canal de decisiones.

### Jerarquía visual / densidad

- **[P1] DAG: nodos verificados con borde dashed ámbar.** Los nodos "Verificado"
  se leen como skeleton/bloqueado (dashed + ámbar), no como "hecho" (sólido +
  sage). Contradice el design system ("borde pasa de dashed a sólido" al
  completar; completed = sage).
- **[P1] SHA de commit de 40 chars domina cada card del DAG y cada fila del
  inspector.** Debe ser short-SHA (7) mono; el SHA completo va en hover/copy.
- **[P1] Inspector denso y con jerga.** "Rol · prof.: leaf · d1", "Alcance: — ·
  guessed", "Produce rev.: SlugifyExport@1" sin agrupar ni explicar. Falta:
  duración, dependencias upstream/downstream explícitas, último evento, riesgo de
  conflicto como sección.
- **[P2] Canvas del DAG infrautiliza el espacio:** root pegado a la izquierda,
  hijos apilados a la derecha, hueco central grande.

### Confianza / demo-readiness

- **[P1] Botones del gate se superponen** en la columna angosta del chat cuando
  hay 4 opciones ("Re-planificar subárbol" pisa "Aceptar fallo y continuar").
- **[P1] "Orquestador · Reconectando…"** persistente en runs terminales: alarmante
  para un run ya finalizado (el SSE reintenta sobre un run cerrado).
- **[P2] Hydration mismatch** de `react-resizable-panels` (layout persistido
  `chat:31.25` vs server `30%`): warning solo-dev, ensucia la consola.

### Lo que ya está bien (preservar)

- Command Center limpio y enfocado; ejemplos "Probá:"; estimación de costo;
  banner de provider con copy correcto ("No se encontró Claude Code CLI…").
- Modelo de datos sólido: event log → reducer → selectores → view-models puros.
  El inspector es render fino sobre `buildFocusView`. **La arquitectura no es el
  problema; la presentación de la capa de evidencia sí.**

## Dirección de diseño elegida

Dos direcciones evaluadas para la capa de evidencia/observabilidad:

- **Dirección A — "Más campos".** Agregar filas al key-value actual (duración,
  deps, riesgo) manteniendo el formato denso. Rápida pero perpetúa el ruido y no
  resuelve el problema central (los logs/diff crudos).
- **Dirección B — "Sala de control con terminal sobria" (elegida).** Tratar la
  evidencia del nodo como lo que es: **salida de proceso**. El log del agente se
  rinde como una **terminal legible ANSI-aware** (verde=pass, rust=fail,
  ámbar=warn, azul/cyan→neutral por la prohibición de celestes), el diff con
  coloreado sobrio, y el resumen de validación arriba ("15/15 · exit 0"). El
  inspector se reorganiza en secciones con jerarquía, no una lista plana.

**Por qué B:** el valor del producto es *apalancamiento supervisado* — el humano
audita y depura sin leer todos los logs. Eso exige que cuando *sí* abre un nodo,
la evidencia sea inmediatamente legible, no un `<pre>` con `←[32m`. B usa 100% de
datos reales que el backend **ya** expone; es el cambio de mayor impacto por línea
y el más visible en demo. Se combina con A para los campos faltantes (duración,
deps), pero el eje es la legibilidad de la evidencia.

### Bloque 2 — Terminal ANSI-aware + evidencia legible en el inspector (2026-06-20)

Hecho y **verificado en UI real** (run `aaeb1bf7`, nodo `slugify`).

**TDD.** `tests/ansi-terminal.test.ts` (12 casos, rojo→verde) fija un parser ANSI
puro: `apps/web/src/lib/run-model/ansi.ts` (`parseAnsiLog`, `stripAnsi`). Mapea
SGR → tonos semánticos: verde→`pass`, rojo→`fail`, amarillo→`warn`,
azul/cyan→`info`, gris→`muted`. El componente mapea los tonos a **tokens del
design system** (pass→sage, fail→rust, warn→ámbar, info/muted→neutral). La regla
"prohibido celestes" se respeta: azul/cyan nunca pintan un color frío, van a
neutral. Estado en `node`, sin React → testeable como el resto del run-model.

**Render.** `focus-panel.tsx`:
- `TerminalView` (ANSI-aware) reemplaza el `<pre>` plano: el log del agente y la
  consola en vivo ahora se leen como terminal sobrio, sin basura `←[32m`.
- Cada artefacto (diff/log/status) es un bloque con disclosure claro (chevron +
  label humano + meta "N archivos"); el log abre por defecto. **No** se filtra
  más el ref crudo `log://…`; el estado de carga es "label · cargando…" limpio.
- El diff colorea adiciones (sage), eliminaciones (rust) y hunks (ember).
- La consola en vivo muestra pulso ember + "en vivo" cuando el nodo trabaja.

**Read amplification.** El poll de `status://` (cada 4s) ahora **solo** corre si
el nodo está vivo (`live`); en un run terminal se busca una vez y no loopea
(verificado: 0 requests nuevos en 6s sobre el run completado).

**Copy.** "Esperando output visible de Gemini…" → copy neutral
(`el agente`/`en vivo`); comentario obsoleto en `focus-view.ts` actualizado.

**Verificación (evidencia, no afirmación).**
- `tests/ansi-terminal.test.ts` 12/12; `tests/artifacts-status-ref.test.ts` 2/2.
- `tsc --noEmit` (web) exit 0.
- UI real: `passColor rgb(143,189,138)` = sage; `timingColor rgb(169,157,136)` =

### Bloque 3 — Elevación visual integral (Signal Deck + injertos) (2026-06-20)

Pasada de diseño visual fuerte pedida por Francisco. Dirección elegida por un
panel de diseño (workflow Claude Design, 3 direcciones críticas → juez →
spec implementable): **"Signal Deck — observability-grade elevation"** sobre la
identidad ember-on-graphite, con injertos de "Forge" (terminal-craft,
ember-as-heat, press táctil) y "Quiet Forge" (detox mono-uppercase, disciplina de
pesos, tabs segmentadas). Guardrails respetados: radios ≤12px, sombras
restringidas, sin glassmorphism, sin celestes, ember ≤10%, contrast:check.

**Foundation (tokens, `globals.css`).**
- Escala de superficies profundizada (`--cu-bg` #0f1012→#0d0e10; pasos ~3% L)
  para que la elevación se sienta.
- Motor de profundidad por **sombra**, no por borde: nuevas `--shadow-lift` /
  `--shadow-pop` / `--shadow-inset` con catch-light cálido SOLO en el borde
  superior (≤0.04 alpha; nunca un side-stripe). Espejadas en light con receta
  más suave (sin inset cálido sobre blanco).
- Bordes demovidos a "whisper": `--color-border` 0.16→0.11. El borde de
  **controles interactivos** (`--color-border-control`) se mantuvo en 0.50/0.47
  porque está gateado a 3:1 (WCAG 1.4.11) — la des-caja la dan los swaps
  por-superficie a `--color-border`, no debilitar el borde de controles.
- Radios: `--r-md` 4→6, `--r-lg` 8→10, `--r-xl` 10→12 (tope del design system).
- Ritmo de spacing a nivel página (gaps 18→24 / 16→20).

**Bug encontrado y resuelto — sombras de Tailwind.** Tailwind v4 mis-parsea
`shadow-[var(--multi-layer)]` como *color* de sombra y emite vacío: ninguna de
las sombras vía utility de Tailwind se renderizaba (verificado por inspección).
Fix: utilidades de CSS directo en `globals.css` (`.mh-elev-1/2/inset/sheet`,
`.mh-lift` con hover/active, `.mh-press`, `.mh-nav-active`) y reemplazo de todos
los `shadow-[var(...)]` de Tailwind por ellas. `box-shadow: var()` directo sí
resuelve (probado). Confirmado en UI: la card del composer pasó de sombra vacía a
`rgba(0,0,0,0.3) 1px 1px, rgba(0,0,0,0.34) 4px 12px`.

**Componentes.** Button (lift en reposo del primary, pop en hover, press inset en
active — vía `.mh-lift`/`.mh-press`); StatusPill (label de-mono sentence-case +

**Status de fuente única (fix audit P1).** El header derivaba el badge de

header "Completado" === sidebar "Completado".**

**Por-superficie.** DAG nodes (borde whisper + `mh-min-node` con shadow-lift,
hover shadow-pop, ring de selección ember más nítido, dot full-signal, role
de-mono, wash ember 3% SOLO en nodos vivos, +footprint 76→84px); header del

**Verificación.** `tsc --noEmit` (web) exit 0 tras cada bloque; suite completa

`overflow-x-auto` + `shrink-0` por tab + scrollbar oculto. **Verificado**: a

zoom ⇒ nodos más grandes). **Verificado en UI** (`aaeb1bf7`): los 5 nodos
(root + 4 hojas) quedan encuadrados sin corte; centrado correcto.

**Hallazgo de revisión (no era bug).** El "Orquestador · Reconectando…" en runs
terminales es **transitorio** (handshake SSE inicial): pasa a "Conectado" en
~1–2s y aparece el delivery panel. No se toca.

**Verificación (evidencia).** `tsc --noEmit` (web) exit 0; `contrast:check`
dark+light OK; `tests/cockpit-layout.test.ts` 4/4 + `run-phases` 14/14 + `ansi`
12/12; consola del cockpit limpia (solo el info benigno de React DevTools);
screenshots a 1440 / 1100 / 768 px de run completado, fallido y gate.

**Limitación conocida.** A 768px con sidebar expandida los 3 paneles
(sidebar+chat+artefactos) quedan densos; el chat es colapsable como escape. El
header "Omitido" en un run `interrupted` que quedó en gate es estado de datos
pre-existente, fuera de scope de este loop.
